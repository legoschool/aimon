# AI몬스터

초등 5~6학년이 AI를 쓰다 부딪히는 상황 문제 100개를 풀어, 세 스테이지의 AI몬스터 21마리를 정화하는 게임입니다. 설치와 로그인이 없고 그림과 소리를 코드로 만들어서, 인터넷이 끊긴 교실에서도 `index.html`을 더블클릭하면 돌아갑니다.

학생용 주소: https://legoschool.github.io/aimon/

수업 흐름은 [수업활용안내.md](수업활용안내.md), 시트로 기록 모으기는 [구글시트연동.md](구글시트연동.md), 인쇄해서 검토할 문항 전체는 [문항표.md](문항표.md)에 있습니다. 이 파일에는 게임의 짜임과 고칠 곳을 적었습니다.

---

## 세 스테이지

| 스테이지 | 주제 | 아이가 서는 자리 | 새로 열리는 질문 | 마지막 보스 |
|---|---|---|---|---|
| AI 마을 | 저작권, 개인정보, 허위정보 | 잘못을 하는 쪽 | 진짜일까? · 누구의 것일까? · 누가 다칠까? · 나는 왜 이걸 하려 하지? | 생각멈춤몬 |
| 데이터 도시 | 편향, 의존, 조작 | 보이지 않는 장치에 당하는 쪽 | 이건 누구를 위한 걸까? | 다들그래몬 |
| 잿빛 황무지 | 감시, 불신, 소외 | 반과 모둠의 한 사람으로 함께 바꾸는 쪽 | 모두가 그렇게 하면 어떻게 될까? | 어차피몬 |

스테이지마다 그림자몬 여섯과 마지막 보스 하나가 있습니다. 그림자몬 셋을 정화하면 중간 보스가 나타나고, 여섯을 모두 정화하면 지도 한복판에 마지막 보스가 나타납니다. 마지막 보스를 정화하면 엔딩이 열리고, 그 화면의 버튼으로 다음 스테이지로 떠납니다. 문항은 마을 30개, 도시 34개, 황무지 36개입니다.

뒤 스테이지의 함정은 앞 스테이지의 정답 태도를 비틀어 만들었습니다. 마을에서 정답이던 "출처 밝히기"가 도시에서는 치우친 그림을 그대로 두는 핑계가 되고, 황무지에서는 "피하기"와 "참기"처럼 당한 사람이 혼자 떠안는 답이 함정이 됩니다. 그래서 스테이지는 차례대로 열립니다.

## 한 번의 싸움

지도에 서 있는 그림자몬 칸에 올라서면 싸움이 시작됩니다. 아이는 답보다 질문을 먼저 고르고, 그 질문으로 따져야 풀리는 상황 문제를 받습니다. 맞히면 그림자몬의 장악력이 줄고, 틀리면 아이의 신뢰도가 15 깎이며 해설이 나옵니다. 틀린 문제는 다시 나옵니다.

문제가 뜨면 글 길이에 맞춰 2.2초에서 7초까지 보기가 잠기고, 다시 만난 문제는 절반만 잠깁니다. 잠금이 풀리고 0.7초 안에 누르면 다음 문제 잠금이 1.5초씩, 6초까지 늘어납니다. 신뢰도는 깎지 않습니다.

가치볼은 세 조건이 모두 맞아야 던질 수 있습니다.

| 조건 | AI 마을 | 데이터 도시 | 잿빛 황무지 |
|---|---|---|---|
| 장악력 | 30% 이하 | 30% 이하 | 30% 이하 |
| 정답률 | 60% 이상 | 70% 이상 | 70% 이상 |
| 푼 문제 수 | 3개 이상 | 4개 이상 | 4개 이상 |

맞힌 뒤 이유를 한 번 더 묻는 "왜 그럴까?" 보너스는 마을에서 35%, 도시와 황무지에서 60% 확률로 나옵니다. 보너스까지 맞히면 그 문제의 공격이 두 배가 되고, 틀려도 잃는 것은 없습니다.

정화한 가치몬은 자기 주제에 센 질문을 한 마리당 15% 키웁니다. 한 질문은 50%까지만 커집니다. "나는 왜 이걸 하려 하지?"는 그 밖의 가치몬이 한 마리당 5%씩 키우고, 틀려도 신뢰도가 절반만 깎입니다.

마을과 도시의 마지막 보스 앞에서는 같은 질문을 두 번 연달아 쓸 수 없습니다. 황무지의 어차피몬은 볼로 잡지 않습니다. 어차피몬이 "어차피 ~"라고 말을 걸면 아이는 지금까지 모은 가치몬 가운데 그 말에 맞설 한 마리를 고르고, 그 가치몬과 함께 할 대답을 고릅니다. 딱 맞는 가치몬이면 공격이 1.5배, 어울리는 가치몬이면 1배, 나머지는 0.5배입니다. 한 번 싸운 가치몬은 모두가 한 번씩 싸울 때까지 쉽니다. 장악력 360을 다 깎으면 가치몬들이 둘러서서 함께 정화하고, 마지막 엔딩에 세 스테이지를 지나온 여정 증서가 나옵니다.

## 조작

방향키, WASD, 한글 자판의 ㅈㄴㅁㅇ, 화면 아래 방향 버튼으로 움직입니다. 보기와 질문, 볼, 가치몬 카드는 숫자키 1~9로 고르고 엔터나 스페이스로 넘어갑니다. 마우스 없이 끝까지 할 수 있습니다.

오른쪽 위 [글자 보통]은 글자를 세 단계로 키웁니다. 효과음은 켜져 있고 배경음은 꺼져 있습니다. 서른 대가 한꺼번에 음악을 틀면 수업이 어렵기 때문입니다.

## 고칠 곳

| 고치고 싶은 것 | 파일 | 찾는 법 |
|---|---|---|
| 상황 문제 | `data/stage1/questions.js`, `data/stage2/questions.js`, `data/stage3/questions.js` | 문항 번호(`cr_01`, `bi_01`, `sv_01`)로 찾습니다. 번호는 `문항표.md`에 있습니다 |
| 어차피몬의 말과 대답, 짝 가치몬 | `data/stage3/finale.js` | `fn_01`부터 `fn_18`까지 |
| 몬스터 이름, 설명, 교훈, 그림 | 스테이지 폴더의 `monsters.js` | 그림은 16×16 글자 격자라 파일을 열면 모양이 보입니다 |
| 지도, 박사님 도착 안내, 엔딩 글, 의뢰, 증표 | 스테이지 폴더의 `stage.js` | 파일 머리말에 지도 글자의 뜻이 있습니다 |
| 질문 이름, 상성표, 가치몬 강화 폭 | `data/tools.js` | `TOOLS`, `TYPE_CHART`, `TOOL_BOOST_PER` |
| 난이도 숫자 | `src/equations.js` | `BALANCE`는 모든 스테이지, `STAGE_BALANCE`는 도시와 황무지 |
| 어차피몬 싸움의 위력 | `data/stage3/finale.js` 위쪽 | `baseDamage`, `match`. 장악력은 `data/stage3/monsters.js`의 `maxGrip` |
| 대문 제목과 첫 문장 | `index.html` 21~60행 | 아래쪽 카드 세 칸은 `src/title.js`가 data 폴더의 표에서 만듭니다 |
| 시트 연동 주소, 반·번호 받기 | `data/config.js` 12~20행 | `SHEET_ENDPOINT`, `SHEET_ENABLED`, `ASK_CLASS_NUMBER` |

문항 한 개는 이렇게 생겼습니다.

```js
{
  id: "sv_01", type: "surveil", tool: "verify", level: "easy", stage: 3,
  situation: "상황",
  question: "질문",
  options: ["보기", "보기", "보기", "보기"],
  answer: 2,          // 0부터 셉니다. 2는 세 번째 보기
  explanation: "맞히든 틀리든 보여 주는 해설",
  wrongHint: "틀렸을 때 덧붙는 한마디",
  hint: "무엇을 따져봐야 할까요?",   // 생각 열쇠. 답 대신 되묻고, 물음표로 끝냅니다
  why: { question: "보너스 질문", options: ["보기", "보기", "보기"], answer: 0, explanation: "보너스 해설" },
}
```

`id`는 학생 저장본에 남습니다. 바꾸면 이미 푼 학생의 기록에서 그 문항이나 몬스터가 빠지므로, 고칠 때 가장 먼저 지킬 것이 이것입니다. 한 주제에서 질문마다 두 문항 아래로 줄이면 싸움 중에 그 질문 버튼이 금방 잠깁니다. 정답 보기가 가장 긴 보기가 되면 아이들이 읽지 않고 고르므로 보기 길이도 비슷하게 맞춥니다.

## 고친 뒤 확인하기

Node.js가 깔린 컴퓨터에서 이 폴더를 열고 돌립니다.

```bash
node tools/check.js
```

"문제 없음"이 나와야 합니다. 빈 칸, 겹친 번호, 정답 번호 쏠림, 질문마다 두 문항이 있는지, 몬스터 그림 크기, 지도에서 닿지 않는 칸, 어차피몬의 짝 가치몬을 봅니다.

```bash
node tools/make-question-table.js
```

문항을 고쳤으면 이것으로 `문항표.md`를 다시 만듭니다. 문항표를 손으로 고치면 다음에 만들 때 사라집니다.

```bash
node tools/simulate.js 200
```

난이도 숫자를 바꿨으면 완주율을 봅니다. 2026년 9월 14일에 300판을 돌렸을 때 정답률 70% 아이 모형은 마을 34문제, 도시 64문제, 황무지 62문제로 끝까지 갔고, 50% 모형도 진 싸움을 다시 하며 세 스테이지를 모두 마쳤습니다. 어차피몬 앞에서 가치몬을 아무렇게나 고르는 모형은 대답이 33개쯤 들어서, 딱 맞는 가치몬을 찾는 모형(11개)의 세 배였습니다.

브라우저 점검은 `node serve.js`로 연 뒤 http://localhost:5178 에서 합니다. 이 방법은 시트 연동을 끈 채로 엽니다. 배포된 주소에서 점검할 때는 몬스터를 잡기 전에 개발자 도구에서 `window.sendRecord = () => false`를 먼저 실행해야 선생님 시트에 가짜 줄이 쌓이지 않습니다.

## 옆 반 선생님이 쓰려면

사본 만들기, 바꿀 곳, 배포의 세 단계입니다.

1. 사본 만들기. https://github.com/legoschool/aimon 을 열고 오른쪽 위 [Fork]를 누릅니다. GitHub 계정이 없으면 폴더를 통째로 USB에 담아 교실 컴퓨터마다 복사해도 됩니다. 이때 기록은 각 컴퓨터에만 남습니다.
2. 바꿀 곳. `data/config.js` 12~13행 `SHEET_ENDPOINT`를 새로 만든 Apps Script 주소로 바꿉니다(`구글시트연동.md` 1~4단계). 시트를 쓰지 않으면 16행 `SHEET_ENABLED`를 `false`로 둡니다. **주소를 그대로 두면 옆 반 학생 기록이 이 저장소를 만든 선생님의 시트로 갑니다.**
3. 배포. 사본 저장소의 Settings → Pages에서 Branch를 `main`, 폴더를 `/ (root)`로 고르고 Save를 누릅니다. 1~2분 뒤 `https://(GitHub 아이디).github.io/aimon/`에서 열립니다.

## 학년이 바뀌면

시트는 먼저 사본을 떠 둔 뒤 2행부터 마지막 행까지 지웁니다. 1행 제목 줄은 남깁니다. 지우지 않으면 반과 번호가 같은 작년 학생과 올해 학생이 섞입니다. 교실 컴퓨터에 남은 기록은 대문 아래 학생 목록의 [지움]으로 지우거나, 브라우저에서 이 사이트의 데이터를 지우면 사라집니다.

## 게임이 안 열리는 날

학교망에서 github.io가 막히면 폴더를 USB로 복사해 `index.html`을 엽니다. 컴퓨터를 쓸 수 없으면 `문항표.md`를 인쇄해 모둠마다 한 스테이지를 나눠 주고, 보기를 가린 채 상황만 읽게 한 뒤 "무엇을 물어야 할까?"를 먼저 말하게 합니다. 게임에서 하려던 활동이 종이로도 됩니다.

## 새 스테이지를 더하려면

내 판단으로는 아래 여섯 곳을 고치면 됩니다. 엔진(`src/`)은 스테이지 번호를 직접 쓰지 않고 `STAGES` 표를 읽으므로, 엔딩의 여정 증서도 마지막 스테이지를 저절로 따라갑니다.

| 할 일 | 파일 |
|---|---|
| `data/stage3` 폴더를 복사한 `stage4`에서 `addStage`의 `id`, 지도, 몬스터, 문항, 의뢰, 증표 바꾸기 | `data/stage4/*.js` |
| 새 주제를 `TYPES`에 `stage: 4`로 넣고 `TYPE_CHART`의 모든 질문 줄에 그 주제 칸 채우기 | `data/tools.js` |
| 잡는 조건 정하기 | `src/equations.js`의 `STAGE_BALANCE` |
| `<script>` 줄을 스테이지 순서대로 더하기 (점검 도구도 이 목록을 읽음) | `index.html` |
| 도착 안내에 쓸 주제 색 칸 만들기 | `style.css`의 `.tut-chip` |
| 시트에 새 주제 칸을 더하고 창구 버전 올리기 | `구글시트연동.md`, `src/sheet.js`, `src/admin.js` |

가치몬과 함께 싸우는 마지막 싸움을 새 스테이지로 옮기려면 그 스테이지의 마지막 보스에 `party: true`를 붙이고, `FINALE`의 `monsterId`와 파일 위치를 옮깁니다.

## 저작권

몬스터 이름, 그림, 문제, 해설, 소리를 모두 새로 만들었습니다. 포켓몬 계열 공개 프로젝트 두 곳은 파일을 나누는 방식과 잡기 확률 공식의 생각만 참고했고 코드와 그림은 가져오지 않았습니다. 저작권을 가르치는 게임이라서 수업에서 이렇게 말할 수 있습니다. "이 게임도 남의 것을 베끼지 않고 만들었어요."
